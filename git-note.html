⚔️ 從 0 開始的對位轉化：SVN 舊思維解構 🛠️

🔗 核心本質：本地資料夾與 GitHub 的空間幾何關係

許多 SVN 開發者最常卡關的，就是分不清楚「我電腦裡的資料夾」跟「GitHub 網站」到底是怎麼連線的。請看以下的核心解構：

1. 本地資料夾：獨立運作的「密封世界」

當你在電腦某資料夾執行 git init 後，該資料夾就分裂成兩個次元：

  • 看得見的次元（工作區）：你平常肉眼看到、用編輯器修改的程式碼檔案。
  • 看不見的次元（本地資料庫）：隱藏的 .git 資料夾。它是一個完整的資料庫，儲存了你過去每一次 commit 的「全景快照歷史」。

💡 關鍵哲學：這個本地資料夾此時是 100% 獨立的。不論世界上有沒有 GitHub、你有沒有網路，它都具備完整的版本追蹤能力。它不需要附屬於任何伺服器。

2. GitHub：雲端的「多功能鏡像庫」

GitHub 本質上只是**「另一台長年不關機、放在雲端的電腦」**。它上面也跑著 Git。你在 GitHub 上建立的 Repository，其實就是雲端伺服器上的一個資料夾。

3. 那兩者是怎麼產生關係的？（綁定原理）

當你在本地執行這行關鍵指令時：

git remote add origin https://github.com/YourName/repo.git

你是在本地的 .git/config 設定檔裡拉了一條隱形的電話線。你告訴本地大腦：「聽著，以後如果我呼叫 origin 這個代號，指的就是雲端這串 GitHub 的網址！」

* git push：就是把你本地 .git 基地裡的精采歷史照片，打包複製一份「推」上這條線，同步到雲端的資料夾。
* git pull：就是把雲端資料夾裡別人新增的照片，「拉」回你本地的 .git 基地。

🛠️ 從零開始：搭建環境並連上 GitHub 的全步驟

如果你在一台完全乾淨、剛灌好作業系統的 Windows 電腦前，請依照以下鋼鐵流程從 0 做到通：

  1. 第一步：註冊 GitHub 帳號
    至 github.com 註冊，並記好你的 Username 和 Email。
  2. 第二步：安裝 Git 核心主程式
    前往官方下載安裝包並安裝。安裝過程中，預設會勾選 Git Credential Manager (GCM)，這一定要裝！它是負責在幕後幫你處理 Windows 與 GitHub 密碼驗證的神器。
  3. 第三步：啟動 PowerShell 建立全域識別
    打開 PowerShell，輸入以下兩行（讓你的電腦每一次 commit 都能自動蓋上你的店章）： 
    git config --global user.name "你的英文名字"
git config --global user.email "你註冊GitHub的信箱"
  4. 第四步：本地平地起高樓
    移動到安全的本地路徑（如桌面），建立資料夾並初始化： 
    cd ~\Desktop
mkdir my-project
cd my-project
git init
  5. 第五步：第一次的網路身分驗證（最重要的一刻）
    當你第一次執行 git push -u origin main 時，作業系統會偵測到你從未連線過此 GitHub 帳號，此時會彈出一個**「Git Credential Manager」的安全視窗**。
    👉 標準解法：直接點擊 "Sign in with your browser"。系統會導向瀏覽器，只要點擊綠色的 "Authorize" 授權按鈕，驗證即刻完成！GCM 會把一組加密憑證（Token）安全地存入 Windows 的「憑證管理員」中。從此以後，你在這台電腦 push 再也不需要輸入密碼。

🌐 一鍵入魂：GitHub Pages 靜態網站發布機制

想要把你寫好的 HTML 網頁變成全天下都能瀏覽的網站，這是最快的免費託管 SOP：

1. 檔名的神聖慣例：index.html

網頁伺服器遵循**「慣例優於設定」**。網址在沒有指定具體檔案時，預設只會自動開啟 index.html。 如果你任性地使用 singapore.html，發布後的網址尾巴就必須強迫加上 /singapore.html 才能看見。為了網址的美觀與通用，建議首頁一律用小寫的 index.html。

2. 網頁後台發布流程步驟：

  1. 將你的程式碼 git commit 並且 git push 到 GitHub 上。
  2. 在該 GitHub 專案網頁正上方，點擊最右側的 Settings (設定/齒輪)。
  3. 在左側側邊欄的選單中，下滑找到 Pages 標籤並點擊。
  4. 在畫布中央的 Build and deployment -> Branch 區域下，將原本的 None 下拉選單改選為 main 分支（或 master）。
  5. 點擊旁邊的 Save (儲存)。
  6. 等待約 60 秒： GitHub 背景會自動觸發 GitHub Actions 幫你進行雲端編譯與部署。
  7. 重新整理該頁面，頂端會噴出一個漂亮的綠色區塊，顯示：
    Your site is live at https://你的帳號.github.io/專案名稱/

🧠 思維模型對照：SVN 集中式 vs. Git 分散式

動作 SVN 指令 Git 指令 核心差異與內部原理說明
同步最新進度 svn update git pull 把雲端別人寫好的新快照拉回你電腦並融合。
標記準備送出 (無) git add 【Git 獨有暫存區】把修改過的檔案搬上準備打包的舞台。
提交變更 svn commit git commit 僅提交到你電腦本地的 .git 資料庫。完全不需網路。
推上雲端 (自動包含) git push 這步才會正式把本地大腦的歷史紀錄，沿著電話線推上 GitHub。

🪤 新手村終極脫困密技

陷阱一：直接執行 git commit 沒加訊息，被抓進 Vim 編輯器？

別慌！這是所有 Git 新手的成人禮。在充滿波浪符號 ~ 的黑暗畫面中，請冷靜依序按下：

  1. 連續猛按鍵盤左上角的 Esc 鍵數次（確保退出編輯模式，進入天神命令模式）。
  2. 直接在鍵盤盲打輸入：:q!（冒號、q、驚嘆號），再按 Enter 即可不儲存瘋狂逃走。
  3. 若想直接輸入訊息並儲存離開：盲打輸入 :wq（寫入並離開），再按 Enter。

陷阱二：程式碼 push 上去後反悔了，用 Reset 還是 Revert？

教練鐵律：已經 Push 上雲端的紀錄，一律用 git revert！

  • git reset（時光倒流）：直接抹殺過去。如果歷史已經上了 GitHub，這招會導致你的本地歷史比雲端還舊，下次 push 會被雲端無情拒絕。
  • git revert（創造未來的反向操作）：它保留過去。它會貼心地建立一個「全新、往前推進的 commit」，裡面的內容剛好是把你想反悔的那筆 commit 「反向操作」回來（例如把改掉的檔名再改回來）。歷史線非常完美，推上雲端絕對不打架。
git log --oneline     # 查出想反悔的那筆 Hash（如 a1b2c3d）
git revert a1b2c3d    # 進入 Vim 輕鬆打 :wq 離開
git push              # 順暢推上雲端，大功告成！
